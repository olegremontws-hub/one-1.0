# Bath Dream — Client MVP v0.7

Рабочая модель клиентского контура Bath Dream с двумя режимами:

- **автономный** — React + localStorage;
- **full-stack** — React + Node API + OTP + SQLite.

## Пользовательский путь

**Регистрация → ФЛ / ИП / Юрлицо → Мои заказы → Создать заказ → Объект → Помещения → Геометрия → Демонтаж → Смета → Карточка заказа**

## Что работает

- регистрация по телефону или e-mail;
- локальный OTP для разработки;
- серверные OTP challenge и bearer-сессии;
- профили ФЛ / ИП / Юрлица с серверной валидацией;
- SQLite-таблицы AUTH_ACCOUNT / CLIENT_PROFILE / PROJECT / ORDER / PRICE_BOOK / DOCUMENT / PAYMENT / ORDER_REVISION / APPROVAL / AUDIT;
- список заказов, редактирование, дублирование, удаление;
- статусы заказа;
- автосохранение незавершённого заказа;
- объект, этаж и наличие лифта;
- несколько помещений;
- точная и быстрая геометрия;
- окна и двери;
- каталог демонтажа;
- автоподстановка количества из геометрии;
- редактируемые расчётные ставки;
- расчёт работ;
- расчёт отходов: объём, масса, мешки, крупногабарит;
- логистика: упаковка, вынос, погрузка, транспорт, утилизация;
- предварительная смета;
- печать построчной сметы;
- JSON backup/import;
- calculation smoke-test;
- authenticated SQLite API smoke-test;
- production build в CI.

## Требования

**Node.js 22.14+**

```bash
npm install
```

## Автономный режим

```bash
npm run dev
```

Если `VITE_API_URL` не задан, клиент продолжает работать через localStorage.

## Full-stack режим

Самый быстрый запуск:

```bash
npm run dev:full
```

Команда одновременно запускает SQLite API и Vite и автоматически передаёт клиенту `VITE_API_URL=http://localhost:8787`.

Либо вручную скопируйте клиентскую конфигурацию:

```bash
cp .env.example .env
```

Она подключает клиент к:

```
http://localhost:8787
```

В двух терминалах:

```bash
npm run server
```

и

```bash
npm run dev
```

Локально OTP-код показывается прямо в интерфейсе. SQLite создаётся автоматически в `server/bathdream.sqlite`.

## Версионированный прайс

Активный прайс хранится в SQLite и отдаётся клиенту через `GET /api/pricing/active`. Новый заказ получает активную версию, а при сохранении в заказ записывается полный снимок расчётной конфигурации.

Управление из консоли:

```bash
npm run pricing -- list
npm run pricing -- clone "Москва · Демонтаж v2"
npm run pricing -- set-rate <PRICE_BOOK_ID> DEM-FL-006 1750
npm run pricing -- activate <PRICE_BOOK_ID>
```

Старые заказы продолжают использовать собственный снимок прайса.

## Документы заказа

В карточке заказа доступен серверный модуль документов:

- коммерческое предложение;
- договор;
- акт выполненных работ.

Каждое формирование создаёт новую версию. В документ записывается снимок клиента, объекта, состава работ, итогов и версии прайса. Статусы документа: `draft → issued → signed`, также документ можно отменить до подписания.

Подписанный документ не редактируется: для изменений создаётся новая версия.

> Текущие шаблоны являются продуктовым MVP и содержат предупреждение о необходимости утверждения юридической формы перед коммерческим использованием.

## Согласование и история

Каждое содержательное изменение заказа сохраняется как отдельная серверная версия. Для версии фиксируются сумма, объект, помещения, демонтаж, прайс и краткое описание изменений.

Из карточки заказа можно:

- зафиксировать текущую версию на согласование;
- подтвердить расчёт;
- вернуть расчёт на изменения с комментарием;
- увидеть историю версий и суммы;
- увидеть журнал действий по согласованию.

Согласование привязано к конкретной версии заказа, поэтому последующее редактирование не меняет уже зафиксированный снимок.

## Оплаты

В карточке заказа работает план платежей:

- аванс;
- финальный платёж;
- другой платёж;
- плановая дата;
- статусы `planned → paid` или `cancelled`;
- показатели «заказ / оплачено / запланировано / остаток».

Сервер не позволяет распределить платежами сумму больше текущего остатка заказа. Факт оплаты фиксируется отдельной датой.

## Production OTP

В публичном режиме `NODE_ENV=production` сервер требует собственные `OTP_SECRET` и `SESSION_SECRET`.

Для доставки кода можно подключить внешний сервис через:

- `OTP_WEBHOOK_URL`;
- `OTP_WEBHOOK_TOKEN`.

Webhook получает method, contact, code, requestId и срок действия. Это позволяет подключить SMS/e-mail провайдера без изменения клиентской регистрации.

## Важно по расчётам

Текущие цены, коэффициенты отходов и логистические ставки — **расчётная модель v1**, а не публичная оферта. Перед коммерческим запуском прайс и коэффициенты необходимо актуализировать и утвердить.

## GitHub Pages

Статический клиент готов к публикации. В репозитории нужно один раз включить:

**Settings → Pages → Build and deployment → Source → GitHub Actions**

API/SQLite на GitHub Pages не запускаются: для full-stack production сервер нужно разместить отдельно и передать его URL через `VITE_API_URL`.

## Следующий слой

Следующий этап: серверный версионируемый прайс и коэффициенты → документы/договор → оплаты → аудит изменений → менеджерский контур.

Исполнительский модуль в текущую клиентскую MVP не входит.
