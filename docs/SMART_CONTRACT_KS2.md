# Bath Dream — договор-оферта, смарт-смета и КС-2

Статус: **MVP v0.12**

## Клиентский сценарий

**Смета → Договор-оферта → Акцепт → Выполнение → КС-2**

### 1. Смарт-смета

При формировании оферты система фиксирует снимок заказа:

- услугу;
- объект и адрес;
- строки сметы;
- количества;
- ставки;
- итоговые суммы;
- версию прайса.

Для снимка вычисляется SHA-256. Этот отпечаток показывается клиенту в карточке документа.

После формирования новая редакция заказа не изменяет уже созданную оферту.

### 2. Договор-оферта

Клиентский документ содержит:

- стороны и реквизиты;
- предмет услуги;
- зафиксированную смету;
- цену;
- порядок расчётов;
- правило акцепта;
- правило изменения версии;
- порядок выполнения и приёмки.

После выпуска документа клиент нажимает **«Принять оферту»**. Акцепт фиксирует версию документа и переводит заказ в договорной статус.

Любое изменение объёма, количества, ставки или итоговой суммы после этого требует новой версии сметы и новой версии оферты.

### 3. КС-2

Акт формируется только после акцепта оферты и привязывается к её номеру.

MVP повторяет структуру формы КС-2:

- номер документа и дата;
- заказчик;
- подрядчик;
- объект;
- основание / договор-оферта;
- договорная стоимость;
- отчётный период;
- номер по порядку;
- позиция по смете;
- наименование работ;
- код единичной расценки;
- единица измерения;
- количество;
- цена за единицу;
- стоимость;
- итог по акту;
- блок «Сдал / Принял».

## Интерфейс

Документный контур выполнен в минимальном чёрно-белом стиле:

- белый фон;
- чёрный текст;
- серые границы;
- без декоративных цветовых акцентов;
- табличный вид КС-2;
- печатный режим.

## Ограничение MVP

Это продуктовый и технический прототип. Текст договора-оферты, реквизиты сторон, юридически значимый способ акцепта, электронная подпись, налоговые поля и итоговая печатная форма должны быть отдельно утверждены юристом и бухгалтером перед коммерческим использованием.
